# CRM Chat — Deployment Guide

This guide covers deploying CRM Chat using Docker Compose. All services are containerized and can run on any host with Docker installed.

## Prerequisites

| Requirement | Minimum | Notes |
|-------------|---------|-------|
| Docker Engine | 24+ | With Compose V2 |
| RAM | 4 GB | Convex backend is memory-intensive |
| Disk | 20 GB | Media storage grows over time |
| Clerk account | — | [clerk.com](https://clerk.com) — publishable key, secret key, M2M key |
| Telegram API | — | `TG_ID` + `TG_HASH` from [my.telegram.org](https://my.telegram.org) |

## Quick Start

```bash
# 1. Clone and configure
git clone https://github.com/nickcomua/crm-chat.git
cd crm-chat
cp .env.example .env
# Fill in required values (see Environment Variables below)

# 2. Start all services
docker compose up -d

# 3. Generate the Convex admin key
docker compose exec backend ./generate_admin_key.sh
# Copy the output into .env as CONVEX_SELF_HOSTED_ADMIN_KEY

# 4. Deploy Convex functions
cd bins/convex-backend
bun install
CONVEX_SELF_HOSTED_URL=http://127.0.0.1:3210 \
CONVEX_SELF_HOSTED_ADMIN_KEY=<key-from-step-3> \
bun x convex deploy
```

## Services Overview

Docker Compose starts five services:

| Service | Image | Ports | Purpose |
|---------|-------|-------|---------|
| **backend** | `ghcr.io/get-convex/convex-backend` | 3210 (API), 3211 (site proxy) | Self-hosted Convex database + functions |
| **dashboard** | `ghcr.io/get-convex/convex-dashboard` | 6791 | Convex admin dashboard |
| **restate** | `docker.restate.dev/restatedev/restate` | 8080 (ingress), 9070 (admin) | Durable workflow orchestration engine |
| **crm-worker** | `nick395/crm-worker` | — | Rust Telegram client + sync service |
| **web** | `nick395/crm-chat-web` | — | React frontend |

### Service Dependencies

```
restate ─┐
         ├──► crm-worker
backend ─┤
         ├──► dashboard
         └──► web
```

- `crm-worker` shares the backend's network namespace (`network_mode: "service:backend"`) so it can reach Convex at `localhost:3210/3211` — this is required for presigned media upload URLs.
- `dashboard` and `web` depend on `backend` being healthy.
- `crm-worker` depends on both `restate` and `backend` being healthy.

## Environment Variables

### Required

| Variable | Service | Description |
|----------|---------|-------------|
| `TG_ID` | crm-worker | Telegram API ID from [my.telegram.org](https://my.telegram.org) |
| `TG_HASH` | crm-worker | Telegram API hash |
| `CLERK_M2M_SECRET_KEY` | crm-worker | Clerk machine-to-machine secret for worker auth |
| `CONVEX_SELF_HOSTED_ADMIN_KEY` | dashboard | Generated by `generate_admin_key.sh` inside the backend container |
| `VITE_CLERK_PUBLISHABLE_KEY` | web | Clerk publishable key for browser auth |

### Optional

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3210` | Convex backend API port |
| `SITE_PROXY_PORT` | `3211` | Convex site proxy port |
| `DASHBOARD_PORT` | `6791` | Dashboard port |
| `VITE_CONVEX_URL` | `http://localhost:3210` | Convex URL for the frontend |
| `CONVEX_URL` | `http://localhost:3210` | Convex URL for the worker |
| `MAX_MEDIA_WORKFLOWS` | `2` | Max concurrent media download workflows |
| `RUST_LOG` | `info` | Log level for Rust services (`debug`, `info`, `warn`, `error`) |
| `DOCUMENT_RETENTION_DELAY` | `172800` | Convex document retention (seconds, default 48h) |
| `SENTRY_URL` | — | Sentry DSN for error tracking |
| `VITE_SENTRY_DSN` | — | Sentry DSN for the frontend |
| `VITE_SENTRY_ENVIRONMENT` | — | Sentry environment tag |

See [ENVIRONMENT.md](ENVIRONMENT.md) for a complete reference of all environment variables.

## Data Volumes

Docker Compose mounts three persistent volumes under `./target/`:

| Path | Service | Contents |
|------|---------|----------|
| `./target/crm-chat-data` | backend | Convex database files |
| `./target/restate-data` | restate | Workflow state + journal |
| `./target/crm-worker-data` | crm-worker | Telegram session files |

**Back up `./target/crm-chat-data`** regularly — it contains all your Convex data (messages, chats, media references, auth state).

## Production Deployment Checklist

### Before deploying

- [ ] All required environment variables are set in `.env`
- [ ] Convex admin key is generated and configured
- [ ] Convex functions are deployed (`bun x convex deploy`)
- [ ] Clerk authentication is configured (publishable key, secret key, M2M key)
- [ ] Telegram API credentials are obtained and set
- [ ] Firewall rules allow inbound traffic on required ports (3210 for API, frontend port)
- [ ] TLS termination is configured (reverse proxy with HTTPS)

### After deploying

- [ ] All containers are healthy: `docker compose ps`
- [ ] Convex backend responds: `curl http://localhost:3210/version`
- [ ] Restate is healthy: `curl http://localhost:8080/restate/health`
- [ ] Dashboard is accessible at `http://localhost:6791`
- [ ] Frontend loads and Clerk login works
- [ ] Worker connects to Convex (check logs: `docker compose logs crm-worker`)

### Security

- [ ] `.env` file has restricted permissions (`chmod 600 .env`)
- [ ] Convex admin key is not exposed publicly
- [ ] Dashboard port (6791) is not exposed to the internet
- [ ] Restate admin port (9070) is not exposed to the internet
- [ ] HTTPS is enforced for all public-facing endpoints

## Reverse Proxy Setup

For production, put a reverse proxy (nginx, Caddy, Traefik) in front of the services. Example nginx config:

```nginx
# Frontend
server {
    listen 443 ssl;
    server_name crm.example.com;

    location / {
        proxy_pass http://localhost:3000;  # web service port
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

# Convex API (needed if frontend connects directly)
server {
    listen 443 ssl;
    server_name convex.example.com;

    location / {
        proxy_pass http://localhost:3210;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";  # WebSocket support
    }
}
```

Important: Convex uses WebSockets for real-time subscriptions. Your reverse proxy **must** support WebSocket upgrades.

## Monitoring & Observability

### Health Checks

All core services have built-in health checks:

```bash
# Convex backend
curl -f http://localhost:3210/version

# Restate
curl -f http://localhost:8080/restate/health

# Check all container health
docker compose ps
```

### Logs

```bash
# All services
docker compose logs -f

# Specific service
docker compose logs -f crm-worker

# Increase Rust log verbosity
RUST_LOG=debug docker compose up -d crm-worker
```

The worker uses the `RUST_LOG` env var (standard `tracing` / `env_logger` format):
- `info` — normal operation, connection events
- `debug` — detailed sync progress, Restate interactions
- `warn` — recoverable errors, retries
- `error` — failures requiring attention

### Error Tracking

Set `SENTRY_URL` (worker) and `VITE_SENTRY_DSN` (frontend) to enable Sentry error tracking.

### Key Metrics to Watch

| What | Where | Concern |
|------|-------|---------|
| Container restarts | `docker compose ps` | Crash loops |
| Disk usage | `du -sh ./target/` | Media storage growth |
| Convex backend memory | `docker stats backend` | Memory pressure |
| Worker connection state | `docker compose logs crm-worker` | Telegram disconnects |
| Restate invocation backlog | Restate admin API (port 9070) | Stuck workflows |

## Updating

```bash
# Pull latest images
docker compose pull

# Restart with new images
docker compose up -d

# Re-deploy Convex functions if schema changed
cd bins/convex-backend
bun x convex deploy
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| Backend won't start | Check `docker compose logs backend` — may need to regenerate admin key |
| Worker can't reach Convex | Worker uses `network_mode: "service:backend"` — ensure backend is healthy first |
| Media uploads fail | Worker needs `localhost:3211` (site proxy) — verify `SITE_PROXY_PORT` |
| Dashboard shows no data | Verify `CONVEX_SELF_HOSTED_ADMIN_KEY` matches the generated key |
| Restate workflows stuck | Check `curl http://localhost:9070/` admin API, restart restate if needed |
| OrbStack DNS issues | Add `127.0.0.1 backend.crm-chat.orb.local` to `/etc/hosts` or use standard Docker |
